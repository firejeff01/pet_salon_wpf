# 事件風暴分析：客戶回饋第二輪

來源：`pm/spec_customer_feedback_round2.md`

## Bounded Context：顧客自填建檔

### Domain Events（領域事件）

- 自填資料已驗證：飼主與所有有填寫的寵物資料均符合規則。
- 可能重複顧客已發現：身分證字號或電話與既有 Owner 相同。
- 重複建檔已取消：店家看到警告後取消建立。
- 重複建檔已允許：店家確認仍要建立資料。
- 顧客資料已建立：Owner 與所有 Pets 已在同一交易中保存。
- 顧客資料建立已回滾：任一資料失敗後沒有留下 Owner 或 Pet。

### Commands（命令）

- 送出顧客資料：提交飼主、寵物、備註、病史與晶片資料，由顧客／飼主觸發。
- 檢查重複顧客：以身分證字號與電話比對既有 Owner，由系統觸發。
- 取消重複建檔：停止建立並保留畫面內容，由店家人員觸發。
- 允許重複建檔：明確允許系統繼續建立，由店家人員觸發。
- 建立顧客與寵物：在單一交易中保存 Owner 與 Pets，由系統觸發。

### Aggregates（聚合）

- 顧客建檔：負責 Owner 與其 Pets 的整批驗證和建立。
  - 接收命令：送出顧客資料、建立顧客與寵物。
  - 產生事件：自填資料已驗證、顧客資料已建立、顧客資料建立已回滾。
- 重複顧客檢查：負責比對既有 Owner 並取得店家決定。
  - 接收命令：檢查重複顧客、取消重複建檔、允許重複建檔。
  - 產生事件：可能重複顧客已發現、重複建檔已取消、重複建檔已允許。

### Policies（政策／規則）

- 當送出顧客資料時 → 先驗證備註、病史、晶片狀態及所有寵物資料。
- 當晶片狀態為「有」時 → 晶片號碼必填。
- 當晶片狀態為「未填」時 → 不推論為「無」。
- 當「以上皆無」被選取時 → 取消其他病史；反向亦同。
- 當可能重複顧客已發現時 → 暫停建立並要求店家決定。
- 當重複建檔已允許或沒有重複資料時 → 於單一交易建立 Owner 與 Pets。
- 當任一步驟失敗時 → 回滾整批顧客資料。

## Bounded Context：飼主資料生命週期

### Domain Events（領域事件）

- 飼主刪除已要求：店家對選定 Owner 發出刪除意圖。
- 飼主刪除已取消：店家未確認不可復原操作。
- 飼主刪除已阻擋：Owner 或 Pet 已有 Appointment / GroomingRecord。
- 飼主與寵物已刪除：沒有歷史的 Owner 與其 Pets 已在同一交易中刪除。
- 飼主刪除已回滾：刪除過程失敗且資料保持原狀。

### Commands（命令）

- 刪除飼主：要求刪除選定 Owner，由店家人員觸發。
- 確認刪除飼主：確認姓名、寵物數量與不可復原提示，由店家人員觸發。
- 檢查飼主歷史：檢查 Appointment / GroomingRecord，由系統觸發。
- 刪除飼主與寵物：以交易刪除 Pets 與 Owner，由系統觸發。

### Aggregates（聚合）

- 飼主資料：保護 Owner、Pets 與歷史服務資料的一致性。
  - 接收命令：刪除飼主、確認刪除飼主、檢查飼主歷史、刪除飼主與寵物。
  - 產生事件：飼主刪除已要求、飼主刪除已取消、飼主刪除已阻擋、飼主與寵物已刪除、飼主刪除已回滾。

### Policies（政策／規則）

- 當飼主刪除已要求時 → 顯示姓名、寵物數量及不可復原提示。
- 當刪除未確認時 → 不異動任何資料。
- 當 Owner 或 Pet 已有歷史時 → 阻擋永久刪除。
- 當沒有任何歷史且已確認時 → 在同一交易先刪 Pets 再刪 Owner。

## Bounded Context：店家簽名與契約輸出

### Domain Events（領域事件）

- 店家簽名已保存：手寫或匯入圖片已正規化為 PNG 並建立 profile。
- 預設店家簽名已變更：新 profile 成為唯一預設。
- 店家簽名已刪除：確認後移除 metadata 與 PNG。
- 契約簽名已選定：預覽對話框已選定 profile 或空白。
- 契約預覽已更新：PDF 預覽已使用選定簽名快照。
- 店家簽名讀取已失敗：簽名遺失、損毀或無法解碼。
- 契約 PDF 已產生：正式 PDF 使用最後預覽的簽名快照輸出。
- 店家簽名已備份：metadata 與 PNG 已收入備份。
- 店家簽名已還原：metadata 與 PNG 已安全還原。

### Commands（命令）

- 手寫並保存店家簽名：建立命名 profile，由店家人員觸發。
- 匯入店家簽名：從 PNG / JPEG 建立 profile，由店家人員觸發。
- 設定預設店家簽名：指定唯一預設，由店家人員觸發。
- 刪除店家簽名：確認後移除 profile，由店家人員觸發。
- 選擇契約店家簽名：於預覽對話框切換 profile，由店家人員觸發。
- 更新契約預覽：使用選定簽名重新產生預覽，由系統觸發。
- 產生契約 PDF：使用最後預覽快照輸出正式 PDF，由店家人員觸發。
- 建立／還原備份：保存或還原簽名資料，由店家人員觸發。

### Aggregates（聚合）

- 店家簽名目錄：管理多個 profile、唯一預設與簽名 PNG。
  - 接收命令：手寫並保存店家簽名、匯入店家簽名、設定預設店家簽名、刪除店家簽名。
  - 產生事件：店家簽名已保存、預設店家簽名已變更、店家簽名已刪除、店家簽名讀取已失敗。
- 契約輸出：管理預覽、簽名快照與正式 PDF 版本。
  - 接收命令：選擇契約店家簽名、更新契約預覽、產生契約 PDF。
  - 產生事件：契約簽名已選定、契約預覽已更新、契約 PDF 已產生。
- 備份：管理資料庫、契約與店家簽名的一致備份。
  - 接收命令：建立／還原備份。
  - 產生事件：店家簽名已備份、店家簽名已還原。

### Policies（政策／規則）

- 當店家簽名輸入時 → 驗證並重新編碼為受限制的 PNG。
- 當設定新預設時 → 取消舊預設，維持最多一組預設。
- 當刪除預設 profile 時 → 不自動選擇其他 profile。
- 當契約對話框開啟時 → 自動選取預設 profile；沒有預設則空白。
- 當契約簽名已選定時 → 更新預覽並保存該次簽名快照。
- 當產生正式 PDF 時 → 同一快照只套入美容人員簽名與乙方簽章。
- 當店家簽名讀取失敗時 → 顯示警告、改用空白簽名，但不阻擋 PDF。
- 當建立／還原備份時 → 一併安全處理 `signatures/`。
